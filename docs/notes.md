# 西文字母片假名注音 · Latin Katakana for BetterNCM

在日语歌的歌词里, 给**西文字母** (拉丁 / 西里尔 / 希腊) 上方标注**片假名读音**。

这是 [片假名终结者](https://github.com/YXLEI0/katakana-terminator-betterncm) 的反方向: 那个把片假名读成英文, 这个把英文 / 罗马音 / 西文各语种读成片假名

```
きらめく  light  と  clover、それから Sekai へ
        ライト      クローバー            セカイ
```

## 它标什么、不标什么

| | 处理 |
| --- | --- |
| 歌词原文行里的拉丁词 (`light` / `clover` / `Sekai`) | 标片假名读音 |
| 西里尔字母 (`Виват Анастасия`) 与希腊字母 (`Θάλασσα`) | 标 —— 词典层和罗马音层都读不了这两种字母, 整词走语种引擎 (见「西文各语种」) |
| 含汉字的行 | 照标 —— 拉丁字母跟振假名不是同一批字, 没有让位的理由 |
| 播放栏的歌名 / 歌手 | 默认也标 |
| RNP 歌词页的**罗马音层** (`rnp-lyrics-line-romaji`) | 跳过 —— 它本身就是读音, 再标是噪音 |
| RNP 歌词页的**中文翻译层** (`rnp-lyrics-line-translated`) | 跳过 |
| RNP 总览页的两层 (`rnp-lyrics-overview-line-romaji / -translation / -placeholder`) | 跳过 (class 按 RNP 3.0.2 bundle 里的实际名字核对过) |
| RNP 的**复制模式 / 总览视图** (`rnp-lyrics-overview-container`, 以及被隐藏的 `overview-mode-hide`) | 整块跳过 —— 那是 `user-select: text` 用来选中复制的, 注音会跟着被复制出去 |
| 网易云**默认歌词页**的翻译 (`li.line > p:nth-child(2)`) | 跳过 —— 判据是**假名**: 日文原文必有, 中文翻译必无 |
| 别家歌词插件的翻译 / 罗马音层 (class 里含整词 `trans` / `translated` / `romaji`, 或 AMLL 的 `lyricSubLine`) | 跳过 |
| 制作信息行 (作词/作曲/编曲/母带/混音/演唱/尺八/乐队/录音棚/音频编辑/Arranged by…) | 跳过。三层判据: ① **三种写法都认** —— `作词：` (中文标签, 标签里允许括号: `编曲（电子）`)、`作词 Lyricist：` / `尺八 Shakuhachi：` / `录音棚 Recording Studio：` (中文标签 + 空格 + **首字母大写**的拉丁标签)、`Lyricist：` / `Mastering Engineer：` (纯拉丁标签); 结尾必须是冒号 / `by` / 连字符。② 关键词表收了约 120 个词头 (角色 + 乐器 + 声部 + 工种, 中英双向)。③ 标签两个表都没有的长尾 (用户的 `杖鼓 Janggu：`), 靠**前后紧挨着的都是署名行**这条局部规则兜住。标签与名字分成两个元素时也拦得住 (往上找到最近的 `li` / `.rnp-lyrics-line`, 用**整行**的文字判一次) |
| 版权行 (`Copyright` / `©` / `(c)` / `℗` / `All rights reserved` / `Presented by` / `Published by`) | 跳过 —— 开头就足以判定, 不要求后面跟冒号 (`Copyright MGMT :Fann` 这种冒号在名字后面的也算) |
| 缩写 (`you're` / `I'll` / `it's` / `don't`) | 拆成"词干 + 尾巴": ユア / アイル / イッツ / ドント。**必须排在词典前面** —— 折掉撇号后 `I'll` 会撞上 `ill` |
| 常见缩写 (`Mr.` / `Dr.` / `Mrs.`) | 念整个词: ミスター / ドクター / ミセス (`St.` `No.` 这类有歧义的没收) |
| 全大写无元音缩写 (`LDK` / `NHK` / `TV` / `BGM` / `DVD`) | 逐字母读 (判据: 全大写 + 2~6 个字母 + 无元音, y 也算元音) |
| 全大写但**有元音**的缩写 (`SOS` / `QTE` / `YY`) | 也逐字母读, 但**只收 2~3 个字母** —— 4 个以上带元音的基本是词或名字 (`DIVA` ディーヴァ、`QUIX` クワイックス、`KISS` キス)。2~3 个的还要过三道闸门: 不是词典里的词 (`LOVE` / `OK` / `MY`)、罗马音也切不出来 (`SORA` / `KIMI`)、不在英文常用词表里 |
| 打码符号后面的碎片 (`****ed` 的 `ed`) | 留白 —— 判据: **两个以上**的 `*` / `＊` / `×` / `※` 紧挨着它 (单个 `*` 是脚注 / 演奏提示, 后面的词照标: `(*teto sax solo)` 里的 teto テト) |
| 带变音符号的拉丁字母 (`Tōkyō` / `Café` / `déjà`) | 标。长音符 `ā ē ī ō ū` 按罗马音读 (`Tōkyō` → トーキョー); 其它变音符号折成基础字母后查词典 (`Café` → カフェ) |
| 单个字母 | `a` / `i` / `o` 标 (真词: ア / アイ / オ); 其它**小写**单字母不标。**大写**单字母放行给读音层按整行判: 成串的 (`(A, B)` / `A B C`) 读字母名 (エー・ビー), 孤零零一个还是留白 (`A story` 的冠词 A 仍是 ア) |
| 单字母**段标** (`(A:` / `B:` / `A：`) | 留白 —— 那是分句 / 分段的标记, 不是字母名也不是单词。判据只看"这个字母后面紧跟冒号", 所以 `(A, B)` 那种成串的照旧读字母名。**这一判排在最前面**: 机器上攒过的"学会的词" (`a → アー`) 也绕不过它 |
| 呼语 `O` / 连词 `o` (`O Chrysalis` / `tragedia o splendidae`) | 大写 **オー** (歌词里的呼语, "哦 / 啊", 拉丁语 / 英语 / 意大利语都这么写), 小写 **オ** (拉丁语连词 "或", 按语种引擎读) —— 用户截图的拉丁语歌词里两种写法是分开用的 |
| 同一个字母重复的整词 | 看**用法**: 后面紧跟日语词尾 / 助词的 (`“XX”してる`、`XXの`) 留白 (打码 / 占位), 独立写的 (`「YY」`、`YY!`) 按字母名标; 小写 (`xx`) 与 4 个以上 (`XXXX`) 留白。判据只看"后面紧挨着 (可夹一个收尾引号) 的字符是不是平假名" |
| 元音串 (`AAAAA` / `OOO` / `aaa`) | 标 —— 喊叫 / 拉长音, 按那个元音叠出来 (アアアアア) |
| 记号 (`D/N/A`、`N/A`、`A.B.C`、`R&B`、`X-Y`) | **整体逐字母读** (分隔符不发音, `&` 读 アンド) |
| 连字符词 (`e-mail` / `x-ray`) | 按单词读 —— 判据是"每一段都是单个字母"才算记号 |
| 波浪号拉长音 (`feel~ing` / `go~od`) | 当**一个词**读 (フィーリング / グッド) —— 波浪号是拉长音的排版写法, 不是词边界。ASCII `~`、全角 `～`、波ダッシュ `〜` 都认; 结尾的那种不算 (`go~` 还是 `go`) |
| 别的注音插件插进来的节点 (片假名终结者的英文注释、jp-furigana 的振假名) | 整棵跳过 —— 给注解做注解没有意义 |

### 西文各语种 (法语 / 德语 / 拉丁语 / 葡萄牙语 / 荷兰语 / 斯瓦希里语 / 汉语拼音 / 俄语 / 希腊语)

**判定在整行级别** (`src/core/langs.js` 的 `detect`, main.js 的 `lineLang`): 每一行单独打分, 谁分高用谁的拼读; 一行里既有德语又有英语时, 那一行按德语读, 别的英文行照旧。判不出来 (英文行、日语行) 就走原来的词典 / 罗马音 / 英文规则

| 语种 | 判定信号 | 拼读要点 | 例子 |
| --- | --- | --- | --- |
| **德语** | `ä ö ü ß`; und / ist / ich / dich / der / die / ein / wenn… 一整张虚词表 | `w` ヴ、`z` ツ、`v` フ、`s`+元音 ザ行、`sch` シュ、`ch` ッハ / ッヒ、`ei` アイ、`ie` イー、`eu` オイ、元音 + 单辅音 + 元音 = 长音、双辅音只表示"前面元音短" (不读促音) | `die Ruinenstadt` ディー・ルイーネンスタト, `schön` シェーン, `Tränen` トレーネン, `Rückkehr` リュックケーア |
| **拉丁语** | `-us / -um / -ibus / -orum` 词尾、`ae / oe` 双元音、词表里的实词; 还要一个**强信号**才认 (英语里 `-is / -at`、`qu` 也满地都是) | **古典式** (日语里拉丁语的惯例): `c` 一律 カ行、`ti` ティ、`v` ヴ、`ae` アエ、双辅音 `ll / rr / tt` 促音而 `mm / nn` 拨音 | `Vindicia` ヴィンディキア, `Vanitatum sentio` ヴァニタトゥム・センティオ, `dolor` ドロル, `Novum mundum` ノヴム・ムンドゥム |
| **斯瓦希里语** | kwa / ya / wa / na / shujaa / dunia… 一张实词表 (必须**真的命中一个词**, 不然罗马音行 `PA PI PU PE PO` 会被误判) | 开音节语言, 按音节直读 (和日语一样); 鼻音在辅音前收 ン (`mbingu` ンビング、`nchi` ンチ) | `Shambulia` シャンブリア, `Beba silaha` ベバ・シラハ, `Ushujaa` ウシュジャア |
| **葡萄牙语** | `ã õ`、`nh / lh / ç`、重音符号 | `ão` アン (辅音后并成一拍: `coração` コラサン)、`nh` ニャ行、`lh` リャ行、`ch` シュ、`c`+e/i セ/シ、`g`+e/i ジ | `não` ナン, `minha` ミニャ, `filho` フィリョ |
| **荷兰语** | `ij`、`oe / ui / ou / eu`、`sch / ch / g` | `ij` アイ、`oe` ウー、`ui` アウ、`eu` ウー、`g / ch` ハ行、词尾 `-en` ン | `tijd` タイト, `goed` フート, `huis` ハウス, `nacht` ナハト |
| **汉语拼音** | **必须有声调符号或 `ü`**, 而且整行每个词都能切成拼音音节 (否则和罗马字行、法语行分不开) | 声母 + 韵母拼: `zh` ジ、`ch` チ、`sh` シ、`x` シ、`q` チ、`c` ツ、`r` ル、`ong` オン、介音并进声母那一拍 (`xie` シェ、`liu` リュウ) | `wǒ` ウォ, `nǐ` ニ, `zhōng` ジョン, `shàng` シャン |
| **俄语** (西里尔) | 出现西里尔字母即认定 | 辅音 + 元音**合成一拍** (`то` ト, 不是 トオ); 软元音 `и / е / ю / я / ё` 走 イ 段 (`ни` ニ、`те` チェ); `ы` イ、`ж` ジュ、`щ` シチ、词尾 `-ий` イー | `Отчизну` オチズヌ, `восславим` ヴォスラヴィム, `Анастасия` アナスタシヤ |
| **希腊语** | 出现希腊字母即认定 | 辅音 + 元音合成一拍; `ου` ウ、`αι / ει / οι` イ、`μπ` ンブ、`ντ` ンド、`γκ` ング、`θ` サ行、`χ` ハ行、`β` **バ行** (日语里希腊语借词的通行写法: ベータ / ビザンツ / ビオス)、`δ` ド、双辅音促音 | `Θάλασσα` サラッサ, `ουρανός` ウラノス, `άνθρωπος` アンスロポス |
| **法语** | 硬信号 = `é è ê à ç ô û œ`、省音撇号 (`l'eau` / `d'un` / `j'ai` / `qu'il`)、法语排版 (` ?` 前有空格); 软信号 = 法语功能词 (le / je / et / dans / amour…) | `eau / au` オー、`ou / eu` ウ、`oi` ワ、`ch` シュ、`gn` ニュ、元音 + r 收尾拉长 (`amour` アムール) | `je` ジュ, `monde` モンド, `l'eau` ロー, `plus` プリュ |

各语种的细节:

- **判定是"所有候选一起打分、按分数从高到低试"**, 每个语种还有自己的门槛 (拉丁语要强信号、斯瓦希里语要真命中词、拼音要切得开), 门槛没过就顺位给下一个 —— 这一条是踩出来的: 最高分那个被自己的门槛否掉之后, 整行就没人认了 (`L'eau dans son courant…` 就这么丢过)
- **有假名的行就是日语行, 不做外语判定** —— 日语歌里的拉丁词照旧"词典优先"。用户截图: `Ave Musica...仮面の民は誘う(Fortuna)` 原本被判成拉丁语、整行走规则层, 于是手工核过的 `ave アベ` 被引擎的 アヴェ 盖掉; 而同一首歌里带假名的另一行读的是词典 —— 同一个词两行两个读音
- **英语常用词一律倒扣 2 分**, 而且不给"词形分" —— 否则法语行、罗马音行 (`PA PI PU PE PO…` 每个词都是元音收尾) 会被算成斯瓦希里语
- **法语判定沿用 `reading.js` 的老判据** (`looksFrench`, 有它自己的测试), 但分数按"命中了几个法语功能词"加权: 法语和拉丁语的**词形**太像 (`Non, le grand amour ne suffit pas.` 里 grand / pas / non 全是辅音收尾), 只给固定分会被拉丁语压过去
- **短句靠整首投票** (`songLanguage`): `Dominatus` / `Ukuu ukuu` / `Venu` 这种两三个词的短行自己分不够, 整首都是那种语言时按那种语言读 —— 判据是"词形命中率够高 + 没有英语常用词", 所以同一首歌里的英文短行 (`Feel my move`) 不会被卷进去
- **罗马音行不会被外语抢走**: `Yes, PA PI PU PE PO… MA MI MU ME MO MORE JUMP!` 是日语罗马字, 各语种都没有真命中词, 判定返回 null
- **规则层的结果一律 `confident:false`** (拼读是近似), 配了 key 就交给大模型按整句定, 判稳了自动沉淀成离线词条; 借词表命中的是 `confident:true` (那是日语通行写法, 等于人工词条)
- **英外同形异音**的词走规则层, 不吃英文词典 (`langs.js` 的 `HOMOGRAPH`): 法语 plus プリュ / son ソン / grand グラン、德语 die ディー / der デア / Wind ヴィント / Tag ターク; 拉丁语行**整行**都走规则 (古典式和英语读音差得太远)
- **专有名词** (`Paris`) 仍然走词典 —— 词典里有人工核过的写法

### 借词表 (sljfaq)

`src/core/loan.js` 是 `tools/build-loan.js` 从 `tools/vendor/loan/*.txt` 编译出来的**生成物** (勿手改), 数据是 sci.lang.japan FAQ 的 "Which Japanese words come from X?":

| 表 | 条数 | 来源 |
| --- | --- | --- |
| 德语 | 87 | [german.html](https://www.sljfaq.org/afaq/german.html) |
| 荷兰语 | 47 | [dutch.html](https://www.sljfaq.org/afaq/dutch.html) |
| 葡萄牙语 | 33 | [portuguese.html](https://www.sljfaq.org/afaq/portuguese.html) |
| 俄语 | 9 | [russian.html](https://www.sljfaq.org/afaq/russian.html) |

- 记的是**日语通行写法**, 所以外语行上**先查这张表**, 连英语词典都要让路 (`Lied` リート, `bier` ビール, `pao` パン, `норма` ノルマ); 表里没有的才用规则近似
- 表只在该语言的行上生效: `rose` 在法语行是 ロゼ、英文行仍是 ローズ
- 改词表: 直接改 `tools/vendor/loan/<语种>.txt` (每行 `词:片假名`), 然后 `npm run build:loan`; `npm run check` 会核对生成物和 txt 是否一致
- **希腊语没有借词表** —— sljfaq 上没有这一页 (只有葡 / 德 / 荷 / 法 / 俄五张), 希腊语纯走规则层
- 法语那张仍在 `reading.js` 里 (`FR_LOAN`, 130 条), 没收 EDICT 里"日语借过去改了意思"的几个: jupon → ズボン、piment → ピーマン、sabot → サボ、aventure → アバンチュール

## 读音从哪来

五层, 按顺序命中 (`src/core/reading.js` + `src/core/llm.js`)。**顺序用户可调** (设置面板「读音来源顺序」的 ↑↓, 或 `WK.layers(['rule','dict',...])`):

| 默认顺序 | 来源 | 例子 | 可信度 / 行为 |
| --- | --- | --- | --- |
| 1 | **离线词典** (`src/core/dict.js`, 6470 条) | `clover` → クローバー | 确定对, 直接用 |
| 1.5 | **学会的词** (运行期由模型答案沉淀, 见下) | `serendipity` → セレンディピティ | 排在**离线词典后面** (人工 > 沉淀 > 大模型, 和 build-dict 同一个口径): 词典里有的词以词典为准, 词典里没有的才用它; 不对就 `WK.learn.forget()` |
| 2 | **罗马音切分** (歌词里官方写的罗马音) | `sekai` → セカイ | 切得干净就算确定; 但**在英文词表里的词标成"没把握"** (`shake` → シャケ), 交给在线层仲裁 |
| 3 | **大模型校正** (配了 key 时, **带整句歌词当语境**) | `kaleidoscope` → カレイドスコープ | 很准; 等待期间先用低优先那层的读音当暂定值 (注音淡一点), 结果回来就地改写 |
| 4 | **免费接口** (Google en→ja, 只接受纯片假名) | `tick` → ティック (它回的 カチカチ 会被首音校验丢掉) | 同上 |
| 5 | **英文音译规则** (垫底) | `blorf` → ブローフ | 猜的; 只有 3 / 4 给不出、失败或没配时才用 |

### 顺序为什么默认是「词典 > 罗马音 > 在线 > 规则」

规则是拼写音译 (`hello` → ヘッラオ、`question` → クワエサション), 那不是人唱的音, 所以词典外的词优先等在线结果; 词典和罗马音是确定的答案, 不该被在线结果覆盖

### 顺序怎么调、调了会发生什么

一条规则: **只有排在"当前答案"前面的在线层才有资格覆盖它**

- 把**英文音译规则**提到大模型 / 免费接口前面 → 那两个在线层根本不被咨询, **一个请求都不发** (纯离线用法)
- 把**大模型**提到**离线词典**前面 → 连词典命中的词也让模型判一遍 (词典偶有错条目, 这是逃生门)
- 把**免费接口**提到大模型前面 → 有 key 也先信 Google
- 改完顺序会**重扫** (先整篇还原再按新顺序重注), 已注音的词会换来源

补充规则: **"没把握"的本地答案 (`confident:false`) 一律按最低那层算**, 于是排在它后面的在线层就有资格覆盖它。谁算"没把握": 英文音译规则的结果 (本来就是猜的), 以及**落在英文常用词表里的罗马音答案**。用户如果把「英文音译规则」拖到在线层前面 (纯离线用法), 这条名次也跟着变成最优先, 在线层照样不会被打扰

**为什么罗马音也要判"没把握"**: 罗马音层的判据只是"整串能切成日语音节", 于是 `shake`(sha-ke) → シャケ、`open`(o-pe-n) → オペン 这种英文词会被它当成日语罗马字; 而罗马音排在在线层**前面**, 它一答, 大模型就没机会纠正。所以多了一份 `core/enwords.js` (英文常用词表, 生成物, 已剔除词典里已有的词): 罗马音答案只要落在这张表里就标成没把握, 让在线层仲裁; 真正的日语罗马字 (`sekai` / `kaze`) 不受影响

**不参与排序**的是形态层: 记号 (`D/N/A`)、缩写 (`I'll`)、字母名 (`LDK`)、只有长音符的罗马字 (`Tōkyō`)。它们决定的不是"读音该信谁", 而是"这个词该怎么断" —— `D/N/A` 去掉斜杠正好是个词典词条, `I'll` 折掉撇号会撞上 `ill`, 所以永远最先判

**只有一个顺序是"会出事"的**: 「英文音译规则」被排到「离线词典 / 日式罗马音」前面。规则对**每个词**都给得出答案, 排在它下面的层就永远轮不到:

| 症状 | 是谁给的 | 正解 |
| --- | --- | --- |
| `the` → セ | 规则层 | 词典 ザ |
| `this` 显示成规则层的颜色 | 规则层 | 词典 ディス |
| `I'll` → イル | 缩写拆出词干 `I` 走规则层 | 词典 アイ + ル = アイル |
| 读数全都没矫正 | 规则先答了, 大模型不再被咨询 | 词典外的词才该问模型 |

所以设置面板的 ↑↓ **不让这么换** (那一对直接禁用, 悬停有原因); 手改配置 (`WK.layers([...])`) 绕过去的话, 层序区和「大模型校正」区都会报警告。真要"只用规则"也行, 那是有意的选择 —— 只是别以为词典还在工作

**等待期间不空着**: 高优先的在线层还在问时, 先用现成答案当**暂定值** (注音加 `wk-pending` 类、按不透明度设置再乘 0.6), 结果回来由 `annotate.relabel()` **就地改写** (DOM 节点一个都不动)。早期版本是"先不标", 结果一行里只要有一个词在等就整行空着, 而且首个词所在节点已有记录、后面拿到结果也补不上

**失败也要叫一次重扫**: 请求失败后进入退避、`isWaiting` 变成 false, 如果没人通知注音层重新判定, 那行就一直淡着 (实测能淡一整个退避周期)。所以大模型层的失败路径和免费接口一样会调 `onUpdate()`

**不透明度这个设置以前是失效的**: 样式里有一条 `rt.wk-rt { opacity: 1 !important }` (本意是挡住别的插件给注音节点打的 opacity), 它把「注音不透明度」整个压掉了。现在分开处理: `ruby.wk-ruby` (底字) 锁死 1, `rt.wk-rt` (注音) 用用户的设置, 暂定再乘 0.6

**底线**: 在线层没配 key / 正在退避 / 请求失败时, 暂定值就是最终值 (标记去掉), 规则层立刻兜底 —— 断网不会变成一个词都不标

### 大模型校正 (推荐打开)

规则层再怎么写也只是拼写音译, 所以词典之外交给大模型:

- **设置面板 → 大模型校正**: 填 API Key (默认 `https://api.deepseek.com/chat/completions` + `deepseek-chat`, 任何 OpenAI 兼容接口都行), 点「测试连接」当场验证
- **接口地址会自动补全**: 文档里给的 `base_url` (`https://api.deepseek.com` 或 `…/v1`) 照抄粘进来 POST 过去是 **404** (实测: 只有完整地址 `/chat/completions` 那一档返回 200)。现在少一段就补一段, 并把纠正后的值写回输入框; 报错也不是干巴巴的 `HTTP 404`, 而是**地址 + 该改哪儿 + 服务端原话** (401 / 403 / 429 / 5xx 各有对应提示)
- **答案要过两道**: ① 纯片假名; ② **首音校验** —— 只看纯片假名拦不住"意译 / 拟声词" (`tick` 可能回 カチカチ)。校验规则: 词首是稳定辅音时音译首音必然落在对应行上 (t → タ行 + サ行 (θ) + ザ行 (ð)、k → カ行…), 对不上就丢掉并记 miss; h / w / y / 元音开头以及 kn / gn / ps 一律不校验, 免得错杀 `write` ライト、`hour` アワー、`knife` ナイフ
- **外语行整行不做第二道校验**: 那套判据是按**英语**拼写定的, 外语的拼写-读音对应不一样 (拉丁语 `v` 读 ヴ 也读 ワ、德语 `w` → ヴ、`x` → クス), 拿英语口径去卡只会把正确答案判掉。用户报的「Vacuum 一直是黄的」就是这么来的 —— 模型给的 `ワクーム` 被判掉, 而 miss 是**永久**的、还落盘, 那个词就永远停在规则层 (黄色 = 暂定值)。现在外语行只留"纯片假名"这一道
- **放宽校验时顺手清一次老 miss**: 载入缓存时如果没清过 (`western-katakana.llm.misspurge1` 这个小标记), 就把所有"问过但没收下"的记录丢掉一次 —— 老记录里混着被误伤的正确答案, 不清的话那些词要等用户手点「重试没结果的词」。**命中一条都不动**, 只清 miss
- **回答被截断时抢救, 而不是整批丢掉**: 一批词多 (30 个) 时回答可能被 `max_tokens` 切掉、JSON 不完整。老代码整批丢掉并按退避**原样重发同一批**, 于是再失败 —— 真机轨迹里的 `大模型请求失败（响应里没有 JSON），120s 后再试` 就是这个循环, 那些词会永远停在规则层 (用户看到的"一直是黄的, 大模型没来矫正")。现在: ① 严格解析失败就逐条**抢救** `"下标": "读音"` 对, 能对上的先收下; ② 没抢到的**不记 miss** (那是永久记录, 只该留给"模型明确给不出/给错了"), 下一轮重问; ③ 批次**减半** (`batchCap`), 下一轮的回答就不会再被截断, 成功之后自动恢复
- **请求里带整句歌词当语境** (条目 `[{i, w, line}]`, 响应按 `i` 对齐): `read` 在 "read a book" 里是 リード、在 "I read it yesterday" 里是 レッド。缓存键是「**词 + 那句歌词**」, 所以同一句里的同一个词只问一次
- 命中缓存立刻用; 没命中就入队, 攒 30 个词或 400ms 发一次请求, 结果回来自动重扫补上
- 一个词只问一次: **命中和"模型也给不出"都永久落 localStorage**, 重启不重新花钱; 请求失败不写缓存, 按退避冷却重试 (60s 起、翻倍、2 分钟封顶)
- 限流 20 请求 / 分钟、单批 30 词、45 秒超时 (超时会把批次减半重试); **任何异常都只是"这一层不工作"**, 自动退回免费接口那一层
- Key **只存在本机 localStorage**, 除你填的那个接口地址之外不会发到别处, 永远不会进仓库

实测 (真接口, 16 个词典外的词一批问完, 1.5 秒): `precious → プレシャス`、`blossom → ブロッサム`、`twilight → トワイライト`、`nostalgia → ノスタルジア`、`silhouette → シルエット`、`kaleidoscope → カレイドスコープ`

### 离线词典是怎么来的

`src/core/dict.js` 是**生成物**, 由 `tools/build-dict.js` 合并三份词表 (优先级从高到低):

| 来源 | 条数 | 怎么来的 |
| --- | --- | --- |
| `tools/seed-words.js` | 949 | 人工核过: 反转 katakana-terminator 的离线词典得到的真实外来语写法 + 手工补的歌词高频词 + "被罗马音读歪的英文词" + 不发音字母 + 音乐术语 + 法语常用词 |
| `tools/seed-words-learned.js` | 0 | 运行期沉淀: 面板「导出词库素材」→ `npm run promote:learned` 筛选 (见下) |
| `tools/seed-words-llm.js` | 5521 | `tools/expand-dict-llm.js` 让大模型按英文词频 (前 6000) 批量生成的读音 |

**"没歧义的词能不能直接写进词典?" —— 能, 而且这是首选做法。** 规则层是"照拼写猜", 哑音、词尾不发音的 e、`-mb` 这些它猜不出来, 猜出来也没有信心 (`confident:false`, 会再送去问大模型, 等于多花一次钱)。遇到**读法唯一**的词, 直接加一行进 `tools/seed-words.js` 再 `npm run build:dict`:

```js
{ en: "knock", kana: "ノック" },
{ en: "subtle", kana: "サトル" },
```

判据只有一条: **读法唯一**。两可的**故意不收** (`do` / `re` / `mi` / `me` / `mo`: 英文 ドゥー / リー / ミー vs 唱名 ド / レ / ミ), 钉死反而会错; 同理 `St.` (セント / ストリート)、`No.` (ナンバー / ノー) 也不收

**通例能修的就别加词** —— 规则层里已经补了四批:

| 通例 | 例子 |
| --- | --- |
| 词首哑音 `kn-` / `wr-` / `gn-` / `ps-` / `pn-` | `knock` ノック、`wrap` ラップ、`gnome` ノーム、`psalm` サーム |
| 词尾 `-mb` 的哑 b | `comb` コーム、`climb` クライム、`lamb` ラム (词中的 `mb` 修不了: number ナンバー 的 b 发音、plumber プラマー 的不发音, 只能进词典) |
| 词尾 `-ize` / `-yze` | 罗马音层直接拒绝这个形状 (日语罗马字没有以 `-ize` 结尾的动词), 规则层按「辅音 + イズ」读: `memorize` メモライズ、`organize` オーガナイズ、`apologize` アポロジャイズ、`criticize` クリティサイズ; 变形一起管 (`memorizing` メモライジング) |
| 词尾 `-ude` | 那个 e 不发音、u 是长音: `jude` ジュード、`rude` ルード、`gratitude` グラティテュード; `du` / `tu` 按日语惯例读 デュ / テュ (`dude` デュード、`attitude` アティテュード) |

人工优先: 同一个词两边都有时保留人工那份; 生成物只收**纯片假名**, 混进汉字 / 平假名的结果当场丢掉。另有一份**黑名单** (`tools/dict-blocklist.js`, 构建与测试共用): 大模型偶尔会把缩写展开成整词 (`avg` → アベレージ), 这类不进词典

重新生成大模型词表 (需要 `DEEPSEEK_API_KEY`, 约 4.5 分钟 / 8 万 tokens):

```bash
npm run build:dict:llm -- --top 6000 --resume   # 生成 / 续跑 tools/seed-words-llm.js
npm run build:dict                              # 合并进 src/core/dict.js
```

**质量怎么核的**: 拿人工核过的 491 条抽 80 条再问一遍模型, **一致率 95%**; 4 条不一致里 2 条其实是人工那份更差 (`cigarette` 人工 タバコ、`complaint` 人工 クレーム —— 那是"意译"不是"音译"), 另 2 条是两可写法 (ヴィクトリー / ビクトリー)

### 运行期素材 → 离线词典

运行期写不进仓库里的 `src/core/dict.js` (构建产物), 所以分三步:

```
面板「操作 → 导出词库素材」   (或 WK.exportWordsJson())
   ↓ 导出 JSON: 已学会的词 + 大模型缓存命中 + 免费接口缓存命中
存成 data/learned.json        (data/ 已在 .gitignore 里)
   ↓
npm run promote:learned       筛选后写 tools/seed-words-learned.js
   ↓
npm run build:dict            合并进 src/core/dict.js (人工 > 沉淀 > 大模型)
```

**筛选规矩** (`tools/promote-learned.js`, 宁可少收 —— 收错了就是"离线权威"):

| 条件 | 为什么 |
| --- | --- |
| 纯片假名、长度 ≤ 14、键是纯小写字母 | 词典的硬格式 |
| 同一词在多个来源 / 语境里读音**一致** | 靠语境的词 (`read` / `plus`) 钉死一定错 |
| 至少见过 **2** 次 | 只见过一次的可能是运气 |
| 不在 `tools/dict-blocklist.js` 里 | 大模型偶尔把缩写展开成整词 |
| 人工词表里没有 | 人工优先, 谁都不许覆盖 |
| 不是"两可"短音节 (do / re / mi / me / mo / pi…) | 读音取决于语境, 交给大模型每句判 |

大模型词表里已有、但写法不同的: 以这次沉淀的为准, 并在生成物里留一行 `// 原 xxx`。`WK.exportWords()` 返回对象、`WK.exportWordsJson()` 返回带缩进的 JSON (面板那颗按钮会尽量复制到剪贴板, 复制不了就打到控制台)

### 模型答案自动沉淀成离线词条 (「学会的词」)

大模型层是按「**词 + 它所在的那一句**」缓存的 (同一个词在不同句子里读音可能不同), 所以同一句歌词换一首歌再出现, 就得重新花钱问一遍。沉淀下来的词条排在**离线词典后面**(人工 > 沉淀 > 大模型), 词典里没有的词从此不再问模型 —— 省的就是这笔钱 (`src/core/learn.js`)。用户报过 `ave` 被沉淀的 アヴェ 盖掉人工的 アベ, 所以这一档必须排在词典后面

**收词规矩** (刻意保守, 收错了它就是"离线权威"):

| 条件 | 为什么 |
| --- | --- |
| 模型答的读音**和本地层不一样** | 一样就没必要收 |
| 同一个词在**两个不同的句子**里答出**同一个读音** | 只答过一次的可能是"只在这一句里才对" (`read` リード / レッド) |
| **不是"两可"的短音节** | 那些词的读音本来就取决于那句话 |
| 模型后来给了**别的**读音 | 立刻把已收的条目**撤掉** (说明它靠语境) |

- 存在 `localStorage['western-katakana.learned.v1']` (上限 3000 条, 超了丢最久没用过的)
- **单字母一律不收**: 它的读音取决于语境 (冠词 `a` ア / 字母名 `(A, B)` エー / 段标 `(A:` 不标), 词级钉死一个必然出错。载入时还会**一次性清掉**老的单字母词条 (标记 `western-katakana.learned.purge1`) —— 用户机器上那条 `a → アー` 就是这么来的 (模型在 `(A:` 的行里答的), 结果段标一直带着读音
- 面板「大模型校正」那块有一行 `学会的词: N 个 …` 和「清空已学会的词」按钮, 用上的词数 (= 省下的提问次数) 也在那行里
- 控制台: `WK.learn.list()` / `WK.learn.stats()` / `WK.learn.forget('xxx')` / `WK.learn.clear()`
- 按来源上色时它是**深绿**

**已知取舍**: 学会的词是**词级**的 (和词典一样不带语境), 所以对"靠语境"的词 (`read` / `live`) 宁可永远不收 —— 上表第 2、4 条就是为它们设的闸门

### 规则层依据 (sljfaq)

**英文音译规则** (`reading.js` 的 `convertEnglish`) 按 sci.lang.japan FAQ 的 [How do I write an English word in Japanese?](https://www.sljfaq.org/afaq/english-in-japanese.html) 写, 代码里每条规则 / 每张表都注了 `参照 sljfaq：…`。已实现的约定:

- **英式发音优先** (`vitamin` → ビタミン, 不是 バイタミン)
- **非重读 r** (英式不卷舌): `ar/er/ir/ur + 辅音或词尾` → アー, `or` → オー (`car` カー、`bird` バード、`horse` ホース)
- **θ → サ行** (`think` シンク), **ð → ザ行** (`the` ザ、`-ther` ザー)
- **v → バ行**是首选写法 (`love` ラブ), ヴァ / ヴィ / ヴ 只在日语实际那么写的词里用 (`visual` ヴィジュアル)
- `ti` / `di` → ティ / ディ (`Disney` ディズニー), `dz` → ッズ (`goods` グッズ)
- **æ after k → キャ** (`cap` キャップ), 开音节的 `ca` 保持 カ (`camera` カメラ)
- **词尾不发音的 e**: 前面的元音是长音 (`time` タイム), `-ce` / `-ge` 收 ス / ジ (`dance` ダンス、`orange` オレンジ)
- **辅音 + 词尾 y → イー** (`happy` ハッピー、`city` シティ)
- **`-Cle` 词尾** → クル / プル / ブル / トル… (`simple` シンプル、`table` テーブル)
- **m / n 在辅音前收 ン** (`hamburger` ハンバーガー、`London` ロンドン)
- **促音**: 重音光看拼写定不下来, 所以只对**单音节词**的词尾塞音补 ッ (`hot` ホット、`cat` キャット), 其余的靠 `confident:false` 交给上层
- **`-ing` → イング** (`surfing` の サーフィン 是该页单列的例外)

**硬契约**: `englishToKatakana()` 的输出一定是**纯片假名** (ァ-ヶ + ー); 规则层任何一步拼出别的东西, 最后由它统一清掉并把 `confident` 置 false —— 由 `tests/dict.test.js` 的不变量测试守着

**已知缺口** (拼写层决定不了、页面自己也说"先查词典"的情形): θ / ð 拼写同形、`ow` (now / snow)、`oo` (book / moon)、`our` (four / hour / tour)、`-er` 的两个读音、促音落在重读音节上、专有名词 (Disney / Washington)、词典形 (pajamas → パジャマ)。完整清单见 `tests/sljfaq-words.test.js` 的 `KNOWN_GAPS`, **不允许静默跳过**

| --- | --- |
| [jp-furigana](https://github.com/Leleawa/jp-furigana) | 汉字 → 振假名 |
| [片假名终结者](https://github.com/YXLEI0/katakana-terminator-betterncm) | 片假名 → 英文 |
| **本插件** | 西文字母 → 片假名读音 |

三者都会往同一行插节点, 所以 jp-furigana 需要打共存补丁 (同一份补丁三个插件共用)

**补丁有两个版本**, 我们注入的节点类名前缀跟着插件改名走过一轮:

| 版本 | 认哪些前缀 | 什么时候用 |
| --- | --- | --- |
| v1 | `kt-*` / `lt-*` | 插件还叫 latin-katakana 时的补丁 |
| **v2** | `kt-*` / `lt-*` / `wk-*` | 现在这一版。`wk-*` 是本插件改名后的前缀 |

装上的是 v1 时**直接重跑** `npm run patch:furigana` 就会就地升级成 v2 (只改类名枚举和标记位), `--check` 会告诉你打的是哪一版

> **片假名终结者那边也要跟着改**: 它认识本插件的 `lt-ruby` / `lt-rt` (所以文档里写着要 2.1.1 或更新)。插件的 DOM 前缀改成 `wk-` 之后, 它那一侧也得把 `wk-ruby` / `wk-rt` 加进识别表, 否则我们的注音会被它当成外人改的、把行重建 —— 症状和我们当年踩的"一直闪"一模一样。那是另一个仓库 ([katakana-terminator-betterncm](https://github.com/YXLEI0/katakana-terminator-betterncm)), 本仓库没有它的代码

```bash
npm run patch:furigana            # 自动找 C:\betterncm\plugins 里的 jp-furigana*.plugin
npm run patch:furigana -- --check # 已打补丁? 打的是 v1 还是 v2?
npm run patch:furigana -- --force # 以备份为基准重打
```

补丁做五件事 (细节见 `tools/patch-jp-furigana.js` 的注释):

1. `isClean()` 的子节点计数忽略**两家注音插件**的节点 (`kt-*` 与本插件的 `wk-*`, 老版本的 `lt-*` 也认)
2. `restore()` 拆 wrap 前把外来注音暂存, 别一起丢掉
3. observer 忽略注音插件引起的变更 (**闪烁的真正来源**) —— `__ktOwned` / `__ltOwned` / `__wkOwned` 三种标记都认
4. `hostsText()` 的"看得见的原文"排除外来注音的 `rt`
5. `processLine()` 重建完一行后回调 `window.__ktRepairLine(line)`, 让注音**同步**补回去 (第 5 条是"不闪"的关键: 靠 MutationObserver 等下一帧补, 中间那一帧就是可见的一闪; 两个插件都会挂这个钩子, 所以**后加载的那个必须链上去而不是覆盖**)

补丁打在**别人的包**上, jp-furigana 一升级就没了; 补丁工具本身也会变。症状是歌词抽搐、或某个词反复闪 —— `--check` 会告诉你包里的补丁**是不是当前这一版**, 不一致就重跑 `npm run patch:furigana -- --force`

反过来, 本插件也认另外两家的注音节点: `isSkippable()` 会整棵跳过 `kt-ruby` / `fg-ruby` 里面。片假名终结者的注音里装的偏偏是**英文原词** (`<rt class="kt-rt">dream</rt>`), 正是本插件要标的对象

## API 用量

两层在线接口都会**烧钱或吃配额**, 所以面板里有一块「API 用量」:

| 账 | 什么时候清零 |
| --- | --- |
| **本次** (会话内) | 重启客户端 |
| **今天** | 跨天 |
| **累计** | 只有点「清零累计」才清 |

每份账里两层分开记: **请求数 / 成功 / 失败 / 词数 / 字符数**, 大模型那层还记接口响应里 `usage` 给的**输入、输出 token**

- **只统计真正发出去的请求**: 命中缓存不算 (那些省下来的量单独显示); `fetch` 直接抛异常 (请求根本没发出去) 也只记一次失败、不记请求
- **免费接口没有 token 概念**, 用请求数 + 字符数衡量
- **花费是估算**: 填了单价才会显示, 公式就是 `输入 token × 输入单价 + 输出 token × 输出单价`, 单位统一成 元 / 百万 token
- 账本存在 `localStorage['western-katakana.usage']`; 坏了 / 被手改坏都不影响使用 (坏数据一律忽略)
- 控制台: `WK.usage()` 看账本, `WK.usageReset('session'|'today'|'all')` 清零

## 排障

控制台里有一个 `WK` 对象 (`window.WesternKatakana` 的短别名, 两个名字都行; 改名前的 `window.LK` / `window.LatinKatakana` 也仍然挂着, 老脚本不至于失效):

```js
WK.stats()             // 读音 + 大模型 + 在线校正三份统计
WK.read('light')       // 本地那几层的读音: { kana, source, confident }
WK.display('light')    // 页面上实际用的读音 (可能是大模型 / 联网换过的)
WK.dict()['light']     // 词典里有没有这个词 (undefined = 会送到大模型)
WK.scan('light と clover')  // 分词结果
WK.pass()              // 立刻重扫一次
WK.layers()            // 当前读音来源顺序; WK.layers(['rule','dict',...]) 可以直接改
WK.colorize(true)      // 按来源给注音上色; 不带参数 = 看当前状态
WK.lang('Novum mundum omnibus aequum condemus')  // 这一行被判成什么语言: { id: 'la', label: '拉丁语' }
WK.loan()              // 借词表: 条数 + 有哪些语种; WK.loan('de') 看德语那张
WK.stats().lastPass    // 上一轮扫描: 计数 + skips (为什么有行没注音) + retryInMs
WK.llm.check()         // 「大模型到底生效了没有」—— 一句话回答
WK.llm.stats()         // 命中 / 缓存条数 / 待问 / 请求 / 失败 / 退避剩余
WK.llm.test()          // 用当前配置打一次真请求, 返回 { ok, message }
WK.llm.flush()         // 立刻把队列里的词发出去
WK.llm.clearCache()    // 清掉大模型缓存
WK.llm.rejects()       // 最近被拒的模型答案: 哪个词、模型原话、被哪条判据拒的
WK.llm.retryMisses()   // 清掉"问过但没收下"的记录 (= 面板那个按钮)
WK.learn.list()        // 「学会的词」列表
WK.learn.stats()       // 数量 / 待定数量 / 本次用上几个
WK.learn.forget('x')   // 忘掉一个词
WK.learn.clear()       // 全清
WK.exportWordsJson()   // 导出词库素材 (给 npm run promote:learned 用)
WK.usage()             // API 用量账本
WK.usageReset('today') // 清零 (session | today | all)
```

### 大模型「请求全失败」怎么查

先敲 `WK.llm.check()` (或看面板「测试连接」), 它会告诉你 Key 体检结果、最后一条错误、以及下一步该做什么:

| 错误里出现 | 真正的原因 | 怎么办 |
| --- | --- | --- |
| `401` / `403` | Key 不对或没权限 | 多半是粘进来时带了**引号 / 空格 / 整个 `Bearer xxx`** —— 插件会当场洗掉这几种 (面板输入框会显示洗完的值); 否则去服务商后台重新生成 |
| `402` + `Insufficient Balance` | 余额 / 额度用完 | 充值或换 key |
| `429` | 被限流 | 等一会儿; 插件自己也有 20 请求 / 分钟的上限 |
| `404` | 地址不对 | 接口地址一般以 `/chat/completions` 结尾, 别只填 `base_url` |
| `400` | 请求被拒 | 多半是模型名不对, 或者这家接口不认 `response_format` |
| 没有状态码那一句 (`Failed to fetch`) | 网络不通 / 被跨域拦住 | 接口地址要在网易云里能直接访问, 且服务商得允许 `https://music.163.com` 这个来源 |
| `The user aborted a request.` | 插件自己的超时 | 一批词太大或服务商在排队; 插件会自动把批次减半重试 |

### 有些词「大模型一直不矫正」怎么查

按顺序对四件事 (全是只读的控制台命令):

1. **离线词典里有没有** (`WK.dict()['那个词']`) → 有的话按默认层序就**不问模型** (这是设计)。想让模型也过一遍: 把「大模型」拖到词典上面
2. **本地那几层给的是什么** (`WK.read('那个词')`) → 看 `confident`: 是 `false` 才轮得到在线层覆盖; 是 `true` 而且命中了词典, 那就按上面那条走
3. **模型缓存里是什么** (`WK.llm.stats()`) → 有读音就是命中过; 没有则可能是"问过但没收下" (miss)
4. **被拒的记录** (`WK.llm.rejects()`) → 列出「哪个词 / 模型原话 / 被哪条判据拒的」

**黄的 (规则层) 一直不变黄**: 说明这个词的模型答案被判掉了 —— 那是**永久** miss, 还落盘, 重启也不重问。两种处理:

- 外语行上的这类词现在**不会再被判掉**了 (首音校验按英语定的, 外语行已整行跳过), 放宽时还顺手清了一次老 miss (见上)
- 别的词: 点面板的「重试没结果的词」(`WK.llm.retryMisses()`), 只清"问过但没收下"的记录、命中不动

一条 miss 是**永久**的, 还会落 localStorage —— 模型当时给的答案被判掉了 (判据误伤、响应格式不对), 那个词就会一直用本地读音, 重启也不重问。所以面板里有**「重试没结果的词」**: 只清"问过但没收下"的记录 (保留命中), 比「清除校正缓存」温和

### 「某首歌开始读音全都没矫正」怎么查

这个症状 (本地读音照旧、模型一条都不改) 几乎都是**模型层停摆**, 面板「大模型校正」区块会直接写清是哪一种, 并给一个「立刻重试」:

| 面板上写什么 | 真实原因 | 怎么办 |
| --- | --- | --- |
| 这一层没启用 / 没填 API Key | 这层根本没工作 | 打开开关 / 填 key |
| 请求失败后退避中, 还要等 N 秒 | 接口抖了或撞限流 | 等, 或点「立刻重试」 |
| 最近几次请求都没成功 | 连着几批都失败 | 同上; 先看错误是 401 / 402 / 429 / 404 哪一种 |
| 队列里还有 N 个词在等 | 只是还没排到 | 等一会儿, 或把词典放回模型上面减少请求 |
| 有 N 条「问过但没收下」 | 那些词的答案被拒过 (永久 miss) | 点「重试没结果的词」 |

**队列会永远躺着不动**这个坑也修了 (`队列里还有 184 个词在等, 本分钟还剩 20 次额度`): 根因是 `schedule()` 在退避期间直接 return, 而退避结束时**没有任何事件**会再来叫我们, 于是"退避结束后重试"从来没生效过。现在退避里不再直接 return, 而是排到退避结束那一刻再试

面板「大模型校正」区块是**实时**的 (每秒轻量刷新), 会写「还要发 N 次请求、本分钟还剩 M 次额度」, 积压时还会提示「大模型排在离线词典前面 -> 每个词都要问一遍」

### 某个词 / 某一行「一直没注音」怎么查

先分清是**哪一类**:

- **一个词读音不对** → `WK.read('那个词')` 是本地层的答案, `WK.display('那个词')` 是页面实际用的。不一样就说明被大模型 / 联网换过; 一样就用 `WK.llm.rejects()` 看模型当时说了什么
- **一个词没标** → 先看它该不该标: 单个小写字母、打码的重复字母串 (`“XX”してる` 里的 XX) 是**故意留白**。`WK.scan('那一行')` 能看分词结果
- **外语行读得不对** → `WK.lang('那一行')` 先确认判成了哪种语言。判错了 (比如英文行被判成拉丁语) 就把那一行发来补词表; 判对了但读音不对, 优先按「读法唯一就写进词典」加词
- **整行一个字都没标** → 看 `WK.stats().lastPass`:

```
WK.stats().lastPass.skips     // 这一轮被跳过的原因 (文本在动 / 认输期 / 无译文 / 不在区域里…)
WK.stats().lastPass.errors    // 注音时抛异常的那几行
WK.stats().lastPass.retryInMs // 已经安排了多久之后再扫一轮
```

跳过原因是**分层的**, 常见的几种:

| 报告里写 | 含义 | 怎么办 |
| --- | --- | --- |
| `文本在动` | 那一行还在抖 (逐字动画 / 换歌) | 窗口一过自动重试 |
| `认输期` | 这行被播放器 / 别的插件反复重建, 我们主动退避 | 到点会自己补回来; 一直出现就把那行的 class 发来 |
| `不在区域里` | 这行的容器不在歌词选择器里 | 把元素链 (带 class) 发来补选择器; 或临时用「自定义选择器」 |
| `无译文` / `制作信息行` / `版权行` | 翻译层、作词作曲行、`© ℗ Copyright` 行 | 正常跳过, 不是 bug |
| `切不出词` | 单个小写字母、打码的重复字母 | 正常 |

**认输期** (被反复重建时主动退避) 最多 1 分钟、到点自己重试: 触发条件是"注上去 **50ms** 内就被抹掉、且 1.5s 窗口里凑够 3 次"; 退避 1s 起翻倍。RNP 逐字行那种 ~100ms 的重写不再触发认输 —— 我们的补注在 MutationObserver 回调里完成 (赶在下一帧之前), 屏幕上根本看不到空窗

### 罗马音节行: 「PA PI PU PE PO」这种按罗马音读

词典是**英文**词典, 所以 `PI` (パイ)、`PE` (ピーイー)、`ME` (ミー) 这种短音节, 在一首日语歌的**罗马字行**里全是错的 —— 那里要的是 ピ / ペ / メ; 而 `pi` / `pe` / `me` 又在英文常用词表里, 靠"是不是英文词"分不开

所以看**整行的构成**: 一行里出现 **≥5 个不同的**「≤3 字母 + 能切成罗马音 + 词典有条目但读音不同」的词, 就判定这是罗马字行

- `PA PI PU PE PO` / `MA MI MU ME MO` → 罗马音读法
- `No, no, no, I need you so` (4 个) / `we can go to the sea` (3 个) → 英文行, 保持词典读音
- 命中之后这些词会标成**没把握**: 在线层拿到整句语境还能改回去

另外还要求**整行 ≤3 字母的词占 60% 以上**, 否则长词句也会被算进来。**再加一条: 拼写上像英文的一律不算罗马字行** —— 日语罗马字里没有 θ (`th`)、没有 `ck` / `gh` / `ph`、也没有 `q` 和 `x`, 所以一行里出现 `th|wh|ck|gh|ph|q|x` 就当它是英文行 (`Knock knock! Let me go in and get the ace` 的 `me` 不会读成 メ), 而 `PA PI PU PE PO` / `MA MI MU ME MO MORE JUMP` 一个都没有, 仍然是罗马字行

### 两可的短音节: 交给语境 (大模型), 离线时保持词典读音

`Do` (ドゥー / ド)、`Re` (リー / レ)、`MI` (ミー / ミ)、`ME` (ミー / メ)、`PE` (ピーイー / ペ)、`PI` (パイ / ピ)、`no` (ノー / ノ) 这些**两种读法都成立**, 光看拼写分不出来:

- 它们会被标成**"没把握"**, 由在线层按整句语境决定 —— `「Do」「Re」を重ねて` → ド / レ; 同一批词在英文行里仍是 ノー / ユー / ソー
- 模型给不出来 (或没配 key、离线) 时**保持词典读音**
- 罗马字行里的那些则直接按罗马音显示, 也是"没把握"

**不要把「日式罗马音」拖到「离线词典」前面**: 罗马音层和规则层一样是"能切成音节就收", 那样 `Shoo` → ショオ、`Gimme` → ギッメ、`more` → モレ 全会被读歪 (面板会给出这条警告)

### 怎么判断大模型有没有生效

1. **面板 →「测试连接」**: 真的打一次请求, 成功回 `✅ 接口正常 (…，clover -> クローバー)`, 失败会把**实际请求的地址 + 服务端原话**一起显示
2. **`WK.llm.check()`** 把数字翻译成结论: `API Key: 没填` (正常默认状态) / `请求 0 次 + 全在离线词典里` (没坏, 只是没活干) / `请求 N 次, 命中 >0` (正常) / `失败 >0` (按错误排查) / `退避中` (刚失败过)
3. **对照某个具体词**: `WK.read('zephyr')` 是本地读音, `WK.display('zephyr')` 是页面实际用的 —— 不一样就说明被大模型换过了。先用 `WK.dict()['zephyr']` 确认它不在词典里
4. **看轨迹**: `[llm] 大模型校正回来 16 个词：命中 16` 这类行 (面板上不再有调试转储, 要数字就用 `WK.stats()`)

> 最常见的误会: **大多数歌一个请求都不会发**。6470 条的词典覆盖了英文词频前 6000, 大模型只在遇到词典外的词 (生僻词、人名、乐队名) 时才动

运行轨迹写在 `localStorage` (键 `western-katakana.trace`), 用仓库里的工具读:

```bash
node tools/read-trace.js
```

它落在网易云的 leveldb 里, 值是 Snappy 压缩的、还跨 record 分片 —— 别手工捞。主要看四类行: `[pass]` (每轮扫描结果)、`[llm]` (请求与命中)、`churn 放弃这一行 … peer{…}` (认输退避与对端状态)、`未注音 …` (某处没标上的原因)

## 实现要点

- **只改文本节点, 不改整行**: React 持有的原文本节点尽量保留 (只切短), 否则它的引用失效可能把页面搞崩; 底字逐字节保持原文
- **不改任何既有元素的 class**: 标记一律用 `data-wk-*`。改别人的 class 会让对方插件判定"这行变了"并重建整行, 我们的注音跟着被丢掉
- **补注音赶在下一帧之前**: 观测到 DOM 变更后用 `requestAnimationFrame` 立刻补, 而不是防抖
- **靠"活了多久 + 窗口内几次"分辨打架与正常重绘**: 注音被重建掉时 `age` 小于 **50ms** **且** 1.5s 窗口里凑够 3 次, 才算对方在无条件重建, 此时才认输退避 (1s 起翻倍、1 分钟封顶)。RNP 的逐字行大约每 100ms 重写一次内容 —— 旧门槛 (150ms) 会把它判成打架, 三轮就进认输期, 那一行在退避窗口里完全没有注音; 而补注在 MutationObserver 回调里完成, 100ms 的空窗根本到不了屏幕
- **"文本一直在变"的判定是滑动窗口, 不是黑名单**: 同一个宿主的可见文本在 3 秒内变了 3 次以上才在这一轮放弃它; 窗口一过自动重试, 而且**每次扫描都判窗口是否过期** (老版本只加不减, 而网易云换歌 / 滚动会复用同一批 `<li>` / `<p>` 只换文本, 于是同一行复用 3 次后永远不注音)
- **跳过之后必须自己安排下一轮**: `pass()` 返回 `retryInMs` (文本在动 = 窗口剩余时间, 认输期 = 退避剩余时间), `main.js` 据此排下一次扫描。换歌之后页面若不再变动 (歌是暂停的, 歌词只渲染一次), 就再也没有事件来触发扫描
- **`the` 读成セ / 首音校验**: `t` 开头允许 タ行 + サ行 (θ 的 th) + ザ行 (ð 的 th)。漏掉 ð 那一行时, 模型对 `the` 答的 ザ (正确的) 会被判成"不是音译"丢掉
- **行首就是拉丁词的行, 不摘掉原文本节点**: 把它清空、注音插在它后面 —— 框架攥着那个节点的引用, 换歌时执行的是 `node.value = 新歌词`, 节点一脱链那句写操作就石沉大海
- **只读别人的状态做诊断**: `peer{dirty=… hosts=… ktOwn=… 原文一致=…}` 直接读 jp-furigana 的 expando, 不改它任何东西
- **真机状态可以直接从网易云的 leveldb 里读出来**: `node tools/read-trace.js` 读轨迹, `--key <键> --raw` 读别的键 —— 排障时这两条最有用: `--key western-katakana.llm.v1` 看模型缓存里每个词的读音 / 被拒原因 (`miss:true` + `why`), `--key western-katakana.learned.v1` 看沉淀下来的词条。**"某个词一直是黄的" 用这两条一眼就能定案** (缓存里是 miss? 压根没问过? 还是被沉淀成了错的读音?)
- **默认歌词页的"原文 + 翻译"靠结构判, 不靠 class**: 默认页是 `ul#mod_pc_lyric_record.lyric > li.line > p × 2` (第一个 `<p>` 原文、第二个是翻译)。所以歌词选择器**越细的排越前**, 收集区域时同一个 `<li>` 只留一块, 判据是**假名有无**; 这两条只对"歌词"那组选择器生效, 播放栏不套用

## 已知限制

- **规则音译只是兜底**: `hello` → ヘッラオ 这种还不准。配了大模型 key 之后词典外的词也交给模型, 正常情况下看不到规则层的输出
- **规则层在若干拼写上比老版本更差** (诚实记账): `my` → マイー、`cake` → キャケ、`third` / `shirt` 这类「二合字母 + r」、`horse` 的词尾 `-se`、`memory` → メモーイー。这些词全都在词典里, 真机上走不到规则层; 走得到的只有词典外的专有名词, 那正好是大模型层的地盘
- **规则层依据的那张表里, 有些例子拼写决定不了读音**: `ow` (now / snow)、`oo` (book / moon)、`our` (hour / tour)、`θ/ð` (think / the)、`-er` 的两个读音 —— 完整清单见 `tests/sljfaq-words.test.js` 的 `KNOWN_GAPS`
- **人工词表里有少量"意译"而非"音译"的条目**: 那批是从"片假名外来语 → 英文"反转来的, 所以 `cigarette` 是 タバコ、`complaint` 是 クレーム (日语里就这两个词, 但歌词里唱出来更像 シガレット)
- 罗马音路径按 `di → ヂ` 切分, 所以 `diorama` 走罗马音会得到 ヂオラマ; 正常走词典拿到 ジオラマ
- 桌面歌词不生效 (原生窗口, 够不到); 汉字振假名是 jp-furigana 的活
- **外语拼读都是近似**: 德语的词重音、俄语的重音与元音弱化 (非重音的 `о` 读 а)、葡语的鼻化程度、拉丁语的音节长短都靠拼写定不下来 —— 这些一律 `confident:false`, 配了 key 交给大模型按整句定。**希腊语没有借词表** (sljfaq 上没有这一页), 全靠规则
- **语种判定可能判错**: 单看一行分不出来时会按整首投票 (`Dominatus` 这种短行) —— 一首歌里外语和英语混得很碎时, 短行有可能站错队; 一个词一行 (`Venu`) 也兜不住, 会走词典 / 罗马音
- **汉语拼音只认带声调符号或 `ü` 的写法**: 不带调的 `ni hao` 和日语罗马字行 (`PA PI PU PE PO`) 长得一样, 不敢认 —— 那一侧宁可留给罗马音层
- 大模型层要自己填 key (**只存本机 localStorage**); 不填也能用, 只是退回免费的 Google 接口。Google 那条依赖**非公开**接口, 可能失效或被限流

## 开发

需要 **Node ≥ 22.22.2** (`jsdom 30` 的引擎要求)

```bash
npm install
npm test              # 跑单元测试 (node --test)
npm run test:serial   # 逐个文件跑; 受限环境里 node --test 起不了子进程时用这个
npm run check         # 静态自检 (语法 / manifest / 读音词典 / 密钥)
npm run build         # 打包
npm run install:plugin  # 复制到 C:\betterncm\plugins
npm run verify:install  # 核对装上去的那个包和当前 src/ 是否逐字节一致
npm run promote:learned # 运行期素材 → tools/seed-words-learned.js
```
